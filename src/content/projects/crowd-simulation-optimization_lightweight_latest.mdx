## Overview

一方向流・対向流・交差流などの歩行者フローをブラウザ上で再現し、**移動ルールや空間条件によって集団の流れがどう変化するかを比較・評価できる人流シミュレータ**です。

シナリオは **Simple Flow / Bidirectional Flow / Crossing Flow** の3種類を用意しています。Simple Flowでは単一のOriginからDestinationへ移動し、Bidirectional Flowでは互いに逆方向へ進む2つのFlow、Crossing Flowでは直交する2つのFlowを同時に発生させます。異なるFlowのエージェントも同じ局所回避の対象となるため、対向・交差による相互作用を含めて観察できます。

移動ロジックは、**「目的地までどの道筋で進むか」を決める大域経路探索**と、**「周囲の人をどう避けるか」を決める局所回避**に分離しています。それぞれ2方式を用意し、同じマップ・エージェント数・移動パラメータ・乱数条件・評価時間で4通りの組み合わせを比較できます。

ブラウザでは人流をリアルタイムに観察しながら、エージェント数や速度、壁などの条件を変更できます。Simple FlowではOrigin / Destinationの位置も編集できます。また、描画を省略した評価用シミュレーションで **平均到達時間・最大混雑度・到達率** を計測し、移動モデルや壁配置による違いを数値で比較します。

さらに、壁を自由な場所へ逃がすのではなく、**Placement Zoneとして与えた設計可能領域の中で、シミュレーション評価が改善する壁配置候補をGA（遺伝的アルゴリズム）で探索**します。人流を可視化するだけでなく、**シナリオ設定 → 観察 → 定量評価 → 制約付き配置探索**までを一つの検証フローとして扱える構成にしています。

## Motivation

創発現象やマルチエージェントシステムへの関心から、個々のエージェントに移動ルールを与えたとき、相互作用や空間構造によって集団全体の流れがどのように変化するかを、自分で条件を変えながら確かめられる環境を作りたいと考えました。

開発当初は単一のStart → Goalを中心に扱っていましたが、その条件だけでは人流同士の相互作用が少なく、壁配置探索でも壁を主要な導線から遠ざけるだけの候補が有利になりやすいという課題がありました。

そこで、**対向流・交差流を含む複数ODシナリオ**と、壁を配置できる範囲を明示する **Placement Zone** を導入しました。単に「最適な配置」を求めるのではなく、与えた設計条件の中で複数の配置候補をシミュレーションし、同じ指標で比較することを重視しています。

## Technical Challenges & Solutions

### 1. シナリオと移動モデルを分離して比較可能にする

人流の挙動を比較するには、「誰がどこからどこへ移動するか」と、「各エージェントがどのルールで移動するか」を分けて扱える必要があります。

本システムでは、ScenarioがOrigin-Destination Flowを定義し、その上で大域経路探索と局所回避を交換可能なモデルとして適用します。

#### シナリオ

| Scenario               | Flow          | 観察対象                     |
| :--------------------- | :------------ | :--------------------------- |
| **Simple Flow**        | 1方向         | 単純な一方向流               |
| **Bidirectional Flow** | 2方向の対向流 | すれ違い・対向による相互作用 |
| **Crossing Flow**      | 直交する2方向 | 交差部での相互作用・混雑     |

#### 移動モデル

| 分類             | 手法                       | 概要                                                                               |
| :--------------- | :------------------------- | :--------------------------------------------------------------------------------- |
| **大域経路探索** | **A\***                    | 現在位置からDestinationまで、壁を避ける経路を探索して移動する                      |
| **大域経路探索** | **Flow Field**             | FlowごとにDestinationへ向かう方向場を計算し、同じFlowのエージェントで共有する      |
| **局所回避**     | **Force-based separation** | 周囲の人との距離に応じて反発を与え、特に近距離では反発を強めて接近を避ける         |
| **局所回避**     | **Social Force Model**     | Social Force Modelを参考に、周囲の人との距離に応じた指数的な反発を与える簡略モデル |

Flowの所属に関係なく周囲の歩行者を局所回避の対象とし、近距離では互いの存在に反応するようにしています。また、極端に重なった場合だけ簡易的な位置補正を行い、人物同士がほぼ無反応に透過し続ける状態を抑えています。

大域経路探索と局所回避を独立した設定として持つことで、**A\* / Flow Field × Force-based separation / Social Force Model** の4通りを同じ条件で比較できます。

### 2. リアルタイム観察と繰り返し評価を同じモデルで扱う

ブラウザ上で人の動きを観察する処理と、多数の条件を繰り返し評価する処理では必要な処理が異なります。

- **Real-Time Simulation**  
  Go側で約50ms間隔（20Hz）でシミュレーションを更新し、計算済みのエージェント状態をWebSocketでブラウザへ配信します。
- **Evaluation without Rendering**  
  条件評価ではライブ表示と同じ移動ロジックを利用しながら、WebSocket配信や画面描画を省略して固定時間だけシミュレーションを進めます。
- **HTTP API**  
  現在配置の評価、4通りの移動モデル比較、GAによる壁配置探索などを単発処理として実行します。

観察用と評価用で移動ロジックを二重実装せず、同じモデルをリアルタイム表示と繰り返し評価の両方に利用しています。

### 3. 共通指標と乱数条件による比較可能性

移動モデルや壁配置を比べる際、見た目だけではなく同じ指標で定量化し、乱数条件も揃えて比較できることを重視しました。

#### 評価指標

| 指標                                   | 内容                                                          | 評価したいこと                       |
| :------------------------------------- | :------------------------------------------------------------ | :----------------------------------- |
| **平均到達時間** (`avg_goal_time_sec`) | Destination到達までの時間。未到達の場合は評価時間上限を用いる | より短時間で目的地へ到達できるか     |
| **最大混雑度** (`max_density`)         | 評価中に1つのグリッドセルで観測された最大エージェント数       | 一部の場所に人が集中しすぎていないか |
| **到達率** (`goal_reach_rate`)         | 評価開始時のエージェントのうちDestinationへ到達した割合       | 行き詰まりや未到達が発生していないか |

平均到達時間と到達率はシナリオ内の全移動エージェントを対象に集計します。最大混雑度は実世界の「人 / ㎡」を推定するものではなく、条件間を比較するための簡易指標です。

未到達者を平均到達時間から除外すると、到達率の低い条件ほど平均時間が短く見える可能性があるため、未到達者には評価時間上限を与えて全エージェントを平均へ含めます。

#### 乱数条件の分離

比較と探索を再実行できるよう、乱数を2系統に分けています。

- `simulation_seed`: エージェントの初期位置など、評価シミュレーション側の乱数条件
- `optimizer_seed`: GAの初期個体・選択・交叉・突然変異など、探索側の乱数条件

同じScenario・入力条件と2つのseedを固定することで、評価シミュレーションとGA探索を同じ乱数条件で再実行できる構成にしています。

なお、これは同じ条件から探索過程を再現するための設計であり、GAが数学的な最適解を保証することを意味しません。

### 4. Placement Zone内での制約付き壁配置探索

GAによる機能は「最適配置」を保証するものではなく、**与えられた配置可能領域の中で、シミュレーション評価が良い壁配置候補を探索する機能**として位置づけています。

配置した壁は、1回のドラッグで作成したセル群を1つの **WallGroup** として扱います。GAはWallGroupの形状を変えず、グループ全体の位置だけを探索します。

```text
壁配置候補を生成
      ↓
人流シミュレーションを実行
      ↓
平均到達時間・混雑・到達率からFitnessを計算
      ↓
評価のよい候補から次の候補を生成
      ↓
繰り返し
```

Fitnessは小さいほど良いものとし、次の考え方で候補を比較します。

```text
Fitness
=
平均到達時間
+ 混雑ペナルティ
+ 未到達ペナルティ
```

ただし、Fitness以前に配置として成立しない候補は探索対象から除外します。主な制約は以下です。

- WallGroupの全セルが **Placement Zone** 内に収まる
- WallGroup同士や各FlowのOrigin / Destinationと重ならない
- マップ外へ出ない
- いずれかのFlowについてOrigin → Destinationの経路を完全に遮断しない
- 各WallGroupは基準位置から一定範囲内だけ移動する
- WallGroupの形状は維持し、回転・拡大縮小・分割は行わない

探索開始時の現在配置をBaselineとして評価し、GAで得られたBest Candidateと **平均到達時間・最大混雑度・到達率** を並べて比較します。Best Candidateは自動反映せず、ユーザーが選択した場合のみライブマップへ適用します。

## Outcome

本プロジェクトでは、

**シナリオを定義する → 移動ルールをモデル化する → ブラウザで集団挙動を観察する → 条件を揃えて定量評価する → シミュレーション結果を使って制約付き配置探索を行う**

という一連の検証フローを、一つのシステムとして扱っています。

単一のアルゴリズムを実装することではなく、**数理モデルを交換可能な形で実装し、異なる人流条件でも比較可能な形で評価し、その結果を次の探索処理へ接続するところまでソフトウェアとして構成すること**を、このプロジェクトの中心に置いています。

## Current Status

現在は、**Simple / Bidirectional / Crossingの3シナリオ、4通りの移動モデル比較、3指標による定量評価、Placement Zone内でのGAによる制約付き壁配置探索**を実装しています。局所回避についても、Flowの所属に関係なく周囲の歩行者を相互作用対象とし、近距離での反発を強める調整を行っています。

現実の人流データを用いたパラメータ校正や妥当性検証は行っておらず、実世界の人流予測や安全判断を目的としたシステムではありません。最大混雑度は比較用の簡易指標であり、壁オブジェクトも実際の建築壁そのものではなく、配置変更可能な仮設パーティション等を簡略化したモデルとして扱っています。
