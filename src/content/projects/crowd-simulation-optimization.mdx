## Overview

**Go のシミュレーションエンジン、Python のマップ生成、JavaScript / p5.js のブラウザ UI** で構成した、リアルタイム人流シミュレータです。

エージェントは A* などで目的地までの大域経路を求め、他者や壁を避けながら自律的に移動します。ブラウザ上ではシミュレーション条件を変更できるほか、壁・誘導板・ゲート、Spawn / Goal ゾーンを直接編集し、その場で人流の変化を確認できます。

さらに、描画を伴わないヘッドレスシミュレーションと **GA（遺伝的アルゴリズム）・SA（焼きなまし法）・NSGA-II** を組み合わせ、移動時間や混雑度を評価しながらオブジェクト配置を自動探索する仕組みを実装しました。

## Architecture

```text
Python ──生成──> map_config.json ──読込──> Go engine
                                              │
                    ┌─────────────────────────┼────────────────────────┐
                    │ WebSocket /ws           │ HTTP API               │ SSE
                    │ 座標・設定・編集操作    │ 最適化開始/停止/適用   │ 最適化進捗
                    ▼                         ▼                        ▼
                              JavaScript / p5.js（Browser）
```

| レイヤー | 技術 | 主な役割 |
| :--- | :--- | :--- |
| **Simulation Engine** | Go | HTTP サーバー、経路探索、物理演算、衝突回避、ヘッドレス評価、GA・SA・NSGA-II |
| **Map Generation** | Python | 固定障害物、グリッド、Spawn / Goal ゾーンを含む `map_config.json` の生成 |
| **Visualization / UI** | JavaScript, p5.js, Chart.js | エージェント描画、マップ編集、パラメータ操作、最適化結果の可視化 |
| **Communication** | WebSocket, REST API, SSE | 通常シミュレーションの双方向通信と、最適化の制御・進捗配信 |

Python は起動前のマップ生成に限定し、サーバー稼働中の経路探索・物理演算・配置最適化は Go 側で完結させています。

## Technical Challenges & Solutions

### 1. 大域経路探索と局所回避の分離

人流の再現には「目的地へ向かう経路」と「周囲の人や壁を避ける動き」の両方が必要です。これらを一つのロジックに固定すると、アルゴリズムごとの特性を比較しにくくなります。

- **Solution: Pluggable Navigation**
  大域ナビゲーションと局所回避を独立した設定として実装しました。大域経路探索は **A*、Flow Field、Goal Vector / Boids、Theta*、JPS、Potential Field**、局所回避は **Force、ORCA / RVO2、Social Force Model** から選択できます。
- **Path Recalculation**
  壁の追加・削除・移動時には全エージェントの経路を再計算します。誘導板などの影響で経路から大きく外れた場合も、現在位置から再探索することで動的なマップ編集に追従させました。

### 2. リアルタイム性とインタラクティブな編集

シミュレーション結果を観察するだけでなく、条件や空間を変更した結果をすぐ確認できることを重視しました。

- **Solution: Go + WebSocket**
  Go が 50ms 間隔（20fps）で物理演算を行い、計算済みのエージェント座標を WebSocket でブラウザへ配信します。ブラウザ側は p5.js による描画へ専念し、経路の Waypoint 自体は送信しない構成にしました。
- **Incremental Data Delivery**
  毎フレーム変化するエージェント状態とは別に、オブジェクト・ゾーン・設定などの静的データは初回接続時と変更時だけ配信します。
- **Interactive Map Editing**
  壁・誘導板・ゲート、および Spawn / Goal ゾーンの配置・移動・削除に対応しました。連続した同種オブジェクトはグループとして扱い、形状を維持したまま移動できます。

### 3. シミュレーションを用いた配置最適化

オブジェクト配置の良し悪しは、静的な距離だけでは判断できません。各配置で実際に人を動かし、到達時間や密集度を比較する必要があります。一方で、候補数と世代数に比例して計算量が急増します。

- **Solution: Headless Evaluation**
  各配置候補について描画なしのシミュレーションを実行し、`avg_goal_ticks`、`avg_speed`、`max_density`、`goal_reach_rate` を計測します。評価時の疑似乱数シードを固定し、候補間で初期条件を揃えました。
- **Parallelization & Cache**
  候補評価を CPU コア数を上限に並列化し、同一配置の評価結果をキャッシュすることで重複計算を抑えています。
- **Multiple Optimization Strategies**
  単一目的の GA / SA では、平均到達時間・平均速度・最大密度を重み付き Fitness として評価します。NSGA-II では平均到達時間と最大密集度を多目的に扱い、Pareto 解集合を提示します。

## Optimization Flow

配置最適化では、隣接する同種オブジェクトを 8 近傍の連結成分としてグループ化し、その形と属性を維持したまま位置を探索します。ロックしたオブジェクトは固定し、固定壁・ゾーン・他グループと重なる候補は除外します。

```text
現在の配置と最適化条件を送信
  ↓
隣接オブジェクトをグループ化
  ↓
複数の配置候補を生成
  ↓
候補ごとにヘッドレス人流シミュレーション
  ↓
移動時間・速度・密度を評価
  ↓
選択・交叉・突然変異、または各最適化方式の更新処理
  ↓
指定回数まで反復し、最良配置または Pareto 解を返す
```

GA のデフォルト設定は、個体数 20、30 世代、1 候補あたり 1,000 tick です。各世代の最良・平均 Fitness と評価指標を SSE で逐次配信し、Chart.js のダッシュボードへ反映します。計算完了後は結果を自動適用せず、ユーザーが選択した配置だけをライブマップへ反映できるようにしました。

## Core Simulation Features

### Pathfinding & Movement

- A* は 8 方向探索、斜め移動コスト $\sqrt{2}$、ユークリッド距離ヒューリスティックを採用し、壁角のコーナーカットを防止
- エージェントごとに Goal ゾーンを割り当て、Waypoint の先読み平均によって進行方向を平滑化
- 他エージェントとの分離、壁からの反発、壁セルへの侵入防止、誘導板の方向力、ゲート通過時の減速を物理更新へ反映
- timid（慎重）と aggressive（積極的）の 2 種類の個体差を設定可能

### Real-Time Controls

- エージェント数、最大速度、目標引力、分離距離・分離力、壁反発力、減衰率、性格比率を実行中に変更
- 大域経路探索と局所回避の方式をブラウザから切り替え
- シミュレーションの一時停止、エージェントの再配置、編集対象のロックに対応

## Outcome

単一の群衆モデルを可視化するだけでなく、**経路探索・局所回避・動的な空間編集・最適化を一つの環境で比較検証できるシミュレーション基盤**を構築しました。

また、リアルタイム表示用の処理と計算量の大きい最適化処理を分離し、WebSocket・HTTP API・SSE を用途ごとに使い分けることで、操作性を保ちながら反復的な配置探索を実行できる構成にしました。
