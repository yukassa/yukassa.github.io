## Overview

創発現象や群衆挙動への関心から個人開発している、リアルタイム人流シミュレータです。

エージェントは選択した大域経路探索に従って目的地へ向かい、局所回避によって他のエージェントや壁との衝突を避けながら移動します。ブラウザ上では人数・速度・移動方式などを変更できるほか、壁・誘導板や スタート/ゴールゾーンのオブジェクトを設置・変更・削除可能で、その場で人流の変化を確認できます。

さらに、画面描画を省略して計算だけを行う評価用シミュレーションと **GA（遺伝的アルゴリズム）・SA（焼きなまし法）・NSGA-II** を組み合わせ、移動時間・速度・密度を評価しながらオブジェクト配置を探索する仕組みを実装しています。

## Motivation

創発現象やマルチエージェントシステムへの関心から、個々のエージェントの局所的な移動ルールや、壁・誘導板などの環境条件が集団全体の流れにどのような変化を生むかを観察できる環境を作ることから開発を始めました。

開発を進める中で、「人流を可視化する」だけでなく、**経路探索や局所回避方式を変えたときに挙動がどう変わるか**、さらに **環境側の条件を変えることで集団挙動を改善できるか** を比較・探索できるよう、アルゴリズム比較、ボトルネック分析、配置最適化の機能を追加しています。

## Technical Challenges & Solutions

### 1. 大域経路探索と局所回避の分離

人流の挙動を比較するためには、「目的地までどの経路を選ぶか」と「周囲の人や壁をどう避けるか」を独立に扱える必要があると考えました。

- **Pluggable Navigation**  
  大域経路探索と局所回避を別々の設定として実装しました。大域経路探索は **A\*、Flow Field、Goal Vector / Boids、Theta\*、JPS、Potential Field** の6方式、局所回避は **Force、ORCA / RVO2、Social Force Model** の3方式から選択できます。
- **Algorithm Comparison**  
  大域経路探索6通り × 局所回避3通り の全18通りについて、画面描画を省略したシミュレーションで一括評価し、結果をヒートマップ等で比較できるようにしました。
- **Path Recalculation**  
  オブジェクトの追加・削除・移動時には経路を再計算し、誘導板の影響で経路から大きく外れた場合も現在位置から再探索することで、動的な空間変更へ追従させています。

### 2. リアルタイムな観察と空間編集

シミュレーション結果を後から確認するだけでなく、条件や空間を変更した結果をその場で観察できることを重視しました。

- **Go + WebSocket**  
  Go が 50 ms 間隔（20 Hz）でシミュレーションを更新し、計算済みのエージェント座標を WebSocket でブラウザへ配信します。
- **Incremental Data Delivery**  
  シミュレーションの更新ごとに変化するエージェント座標とは別に、オブジェクト・ゾーン・設定などの静的データは初回接続時と変更時だけ配信し、ブラウザ側へ送る情報を分けています。
- **Interactive Map Editing**  
  ブラウザから壁・誘導板やスタート/ゴールゾーンを配置・移動・削除できます。連続した同種オブジェクトはグループとして移動でき、ロックしたオブジェクトは最適化対象から除外できます。モバイルではタッチ操作にも対応しています。

### 3. シミュレーション結果を使った配置探索

壁や誘導板などの配置候補ごとに実際の人流シミュレーションを実行し、**「どの配置ならよりスムーズに移動できるか」**を数値で比較できるようにしました。評価時は画面描画を省略し、計算だけを行うことで、多数の配置候補を繰り返し試せるようにしています。

#### 配置候補を比較するための指標

各候補について、主に以下の値を計測します。

| 指標                                | 内容                                                                     | 評価したいこと                       |
| :---------------------------------- | :----------------------------------------------------------------------- | :----------------------------------- |
| **平均到達時間** (`avg_goal_ticks`) | エージェントがゴールへ到達するまでに要したシミュレーションの平均更新回数 | より短時間で目的地へ到達できるか     |
| **平均速度** (`avg_speed`)          | シミュレーション中のエージェントの平均移動速度                           | 人の流れが滞らず移動できているか     |
| **最大密度** (`max_density`)        | シミュレーション中に観測された最も高い混雑度                             | 一部の場所に人が集中しすぎていないか |
| **到達率** (`goal_reach_rate`)      | ゴールまで到達できたエージェントの割合                                   | 行き詰まりや未到達が発生していないか |

候補間の比較条件をできるだけ揃えるため、評価用シミュレーションでは疑似乱数の条件を固定しています。

#### 複数の方法による配置探索

**GA（遺伝的アルゴリズム）とSA（焼きなまし法）** では、平均到達時間・平均速度・最大密度を1つの評価値にまとめて配置を比較します。どの指標を重視するかはブラウザから調整できます。

**NSGA-II** では、複数の指標を1つの値にまとめず、たとえば「到達時間は短いが混雑しやすい配置」と「多少時間はかかるが混雑しにくい配置」のように、異なる特徴を持つ候補を複数提示できるようにしています。

#### 多数の候補を効率よく評価する工夫

配置探索では、候補ごとにシミュレーションを繰り返すため計算量が大きくなります。そのため、CPUコア数の範囲で複数候補を同時に評価し、同じ配置が再び候補になった場合は以前の評価結果を再利用することで、不要な再計算を減らしています。

また、現在の配置で混雑が起きやすい場所を分析し、その情報を最適化の初期候補生成に利用できるようにしています。

## Outcome

単一の群衆モデルを可視化するだけでなく、**経路探索・局所回避・環境条件を切り替えながら集団挙動を比較し、その結果をもとに配置条件まで探索できる検証環境**を構築しました。

また、リアルタイム表示と計算量の大きい評価・最適化処理を分け、WebSocket・HTTP API・SSE を用途に応じて使い分けることで、インタラクティブな観察と反復的なシミュレーション評価を同じブラウザ UI から扱えるようにしています。

## Current Status

現在はローカル環境で動作する個人開発プロトタイプで、公開デモ環境は未整備です。現実の人流データを用いたパラメータ校正や妥当性検証は未実施であり、実世界の人流を予測するシステムではなく、移動アルゴリズムや環境条件の違いを比較・探索するための検証環境として開発しています。
