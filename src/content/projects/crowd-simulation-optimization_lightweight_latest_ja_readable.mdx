## 概要

人流シミュレータは、**多くの人が空間の中を移動するとき、どこを通り、どこで混み合い、全体としてどのような流れが生まれるかを仮想的に再現するもの**です。

このプロジェクトでは、仮想的な通行人をブラウザ上で動かし、**移動ルールや壁などの空間条件を変えたときに、集団全体の流れがどう変化するかを観察・比較できる環境**を作っています。

例えば、人が全員同じ方向へ進む場合だけでなく、

- **一方向流**：左から右へ進むような単純な流れ
- **対向流**：左右から来た人が互いにすれ違う流れ
- **交差流**：横方向と縦方向の人流が交差する流れ

を切り替えて観察できます。

通行人は、目的地までの経路を選びながら、近くにいる他の人を避けて移動します。異なる方向へ進む人も互いを避ける対象になるため、対向流や交差流では、すれ違いや交差による流れの変化も表れます。

また、見た目だけで比較するのではなく、**平均到達時間・最大混雑度・到達率**という3つの指標で結果を数値化します。

さらに、シミュレーション結果を利用して、**指定した配置可能領域の中で、壁をどこへ移動すると人流が改善するかをGA（遺伝的アルゴリズム）で探索**できます。

人が動く様子を可視化するだけでなく、

**条件を変える → 動きを観察する → 数値で比較する → 配置候補を探索する**

ところまでを一つの検証環境として扱えるようにしています。

## 背景・目的

私は創発現象やマルチエージェントシステムに関心があり、**個々のエージェントに比較的単純なルールを与えたとき、その相互作用から集団全体としてどのような振る舞いが生まれるのか**を、自分で条件を変えながら確かめられる環境を作りたいと考えました。

最初は、通行人が単純にスタート地点からゴール地点へ進むモデルから作り始めました。

しかし、それだけでは人同士の相互作用が少なく、壁配置を探索しても「人の進路を邪魔しない場所へ壁を移動する」候補が有利になりやすいという課題がありました。

そこで、**対向流・交差流のシナリオ**を追加し、異なる方向へ進む人流同士が影響し合う状況も扱えるようにしました。

また、壁をマップ上のどこへでも移動できるようにするのではなく、**壁を配置してよい範囲（Placement Zone / 配置可能領域）**をあらかじめ設定し、その範囲の中から候補を探索する形に変更しました。

このプロジェクトでは、現実の人流を高精度に予測することよりも、**条件やモデルを変えたときに集団の振る舞いがどう変わるかを、同じ環境で観察・比較できること**を重視しています。

## 技術的な課題と工夫

### 1. 「どこを通るか」と「人をどう避けるか」を分ける

人の移動を考えると、

1. **目的地まで、どの道筋で進むか**
2. **近くに他の人がいたとき、どう避けるか**

は別の問題です。

そこで、この2つを別々の処理として実装し、組み合わせを切り替えられるようにしました。

#### 目的地までの経路を選ぶ方法

| 手法           | 概要                                                                               |
| :------------- | :--------------------------------------------------------------------------------- |
| **A\***        | 現在位置から目的地まで、壁を避ける経路を探索して進む                               |
| **Flow Field** | 目的地へ近づく方向をマップ全体にあらかじめ計算し、同じ目的地へ進む人たちで共有する |

#### 近くの人を避ける方法

| 手法                                   | 概要                                                         |
| :------------------------------------- | :----------------------------------------------------------- |
| **Force-based separation**             | 近くの人から離れる向きに反発を加え、距離が近いほど強く避ける |
| **Social Force Modelを参考にした方式** | 周囲の人との距離に応じた指数的な反発を加える簡略モデル       |

これにより、**A\* / Flow Field × 2種類の回避方法**の4通りを、同じマップ・人数・速度・評価時間などの条件で比較できます。

また、局所回避では進行方向が同じかどうかに関係なく、周囲の通行人を避ける対象としています。対向流や交差流でも互いの存在に反応するため、単純に人同士が無視して通り抜け続ける状態を抑えています。

近距離では反発を強め、極端に重なった場合だけ簡易的な位置補正を行っています。ただし、人体の衝突を物理的に厳密再現することを目的としたモデルではありません。

### 2. 一方向だけでなく、対向・交差する人流を扱う

単純な一方向流だけでは、人同士の相互作用が少なく、人流モデルとして観察できる現象も限定されます。

そこで、複数の出発地と目的地の組み合わせをシナリオとして用意しました。

| シナリオ     | 内容                                        |
| :----------- | :------------------------------------------ |
| **一方向流** | 1つの方向へ通行人が移動する基本的なシナリオ |
| **対向流**   | 左→右と右→左の人流が同時に発生する          |
| **交差流**   | 横方向と縦方向の人流が交差する              |

各通行人は自分の目的地へ向かいながら、別の人流に属する通行人とも局所的に避け合います。

これにより、単純な到達時間だけでなく、**すれ違いや交差によってどこに混雑が生まれるか、移動ルールによって流れがどう変わるか**も観察できるようになりました。

### 3. 見た目だけでなく、同じ指標で比較する

シミュレーションを見て「こちらの方が流れが良さそう」と判断するだけでは、条件ごとの差を比較しにくくなります。

そこで、以下の3指標を共通の評価軸として使っています。

| 指標             | 何を見るか                                   |
| :--------------- | :------------------------------------------- |
| **平均到達時間** | 全体として目的地へどのくらい早く到達できたか |
| **最大混雑度**   | 一部の場所に人が集中しすぎていないか         |
| **到達率**       | 評価時間内に目的地へ到達できた人の割合       |

平均到達時間では、評価時間内に到達できなかった通行人も除外せず、評価時間の上限値を到達時間として扱います。

これは、到達できなかった人を除外することで、かえって「多くの人が到達できない条件の方が平均時間だけは短い」という評価になることを避けるためです。

最大混雑度は、実世界の「人 / ㎡」を推定するものではなく、**異なる条件を同じ基準で比較するための簡易的な指標**として使っています。

### 4. 同じ条件で実験をやり直せるようにする

シミュレーションでは、通行人の初期位置などに乱数を使います。また、GAによる配置探索にも乱数が使われます。

乱数条件が毎回変わると、結果の違いが「移動モデルの違い」なのか「たまたま初期位置が違っただけ」なのか判断しづらくなります。

そこで、乱数を以下の2つに分けています。

- `simulation_seed`：通行人の初期位置など、シミュレーション側の乱数条件
- `optimizer_seed`：GAの候補生成・選択・交叉・突然変異など、探索側の乱数条件

同じシナリオ・設定・seedを指定することで、同じ条件から評価や探索をやり直せるようにしています。

### 5. シミュレーション結果を使って壁配置を探索する

人流を観察・評価するだけでなく、その結果を使って、**どの壁配置が比較的良い結果になるか**も探索できるようにしました。

GA（遺伝的アルゴリズム）は、複数の配置候補を作り、それぞれを評価しながら、より評価の良い候補を残して新しい候補を作る処理を繰り返します。

本システムでは、候補となる壁配置ごとに人流シミュレーションを実行し、

- 到達までに時間がかかりすぎないか
- 強い混雑が起きていないか
- 到達できない人が増えていないか

をまとめて評価します。

```text
壁配置の候補を作る
      ↓
その配置で人流をシミュレーションする
      ↓
到達時間・混雑・到達率を評価する
      ↓
評価のよい候補から次の候補を作る
      ↓
繰り返す
```

ただし、壁を自由にどこへでも移動できると、単に人の進路から遠ざける配置が有利になりやすくなります。

そこで、**配置可能領域（Placement Zone）**を設定し、その中だけで壁を移動させます。

また、

- 壁同士が重ならない
- 出発地・目的地と重ならない
- マップ外へ出ない
- いずれかの人流について目的地までの経路を完全に塞がない
- 元の壁形状を変えない
- 基準位置から一定範囲内で移動する

といった制約を設けています。

探索開始時の現在配置と、GAで得られた最良候補について3つの評価指標を並べて比較し、最良候補はユーザーが選択した場合のみマップへ反映します。

ここでいう「最良候補」は、設定した条件と探索回数の中でGAが見つけた候補であり、数学的な最適解を保証するものではありません。

## このプロジェクトで重視したこと

このプロジェクトでは、

**人の移動ルールを作る → 複数の人流を観察する → 条件を変えて同じ指標で比較する → 結果を使って壁配置を探索する**

という流れを一つのシステムとして扱っています。

個別のアルゴリズムを実装することだけではなく、**モデルを交換可能な形で組み込み、同じ条件で比較し、その評価結果を次の探索へつなげること**を重視しました。

また、実際に動かして観察する中で、

- 単純な一方向流だけでは人同士の相互作用が少ない
- 壁を自由に移動できると自明な配置が有利になりやすい
- 異なる方向へ進む人同士の相互作用を適切に扱う必要がある

といった課題が見つかり、シナリオや探索条件、人を避ける処理を見直しています。

## 現在の状況・制限事項

現在は、**一方向流・対向流・交差流の3シナリオ、4通りの移動モデル比較、3指標による定量評価、配置可能領域内でのGAによる制約付き壁配置探索**を中核機能として実装しています。

主要なシミュレーション・評価ロジックについてはテストを行っていますが、ブラウザUIには操作性を含めて調整中の箇所があります。

また、このシミュレータは現実の人流データを用いたパラメータ校正や妥当性検証を行っていません。そのため、**実世界の人流予測や安全判断を目的としたものではありません**。

最大混雑度も実際の人口密度を推定する値ではなく、条件間を比較するための簡易指標です。壁も実際の建築壁そのものではなく、移動可能な仮設パーティションなどを簡略化したものとして扱っています。
