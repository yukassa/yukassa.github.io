## Overview

個々のエージェントの移動ルールや、壁などの空間条件が、集団全体の流れにどのような違いを生むかを観察・比較するためのリアルタイム人流シミュレータです。

シミュレーションでは、**「目的地までどの道筋で進むか」を決める処理（大域経路探索）**と、**「近くの人との衝突をどう避けるか」を決める処理（局所回避）**を分離しています。それぞれ2方式を用意し、4通りの組み合わせを同じ条件で比較できる構成としています。

ブラウザ上では人流をリアルタイムに観察しながら、エージェント数や速度、壁、スタート/ゴールゾーンなどの条件を変更できます。さらに、画面描画を省略した評価用シミュレーションで **平均到達時間・最大混雑度・到達率** を計測し、条件ごとの違いを定量的に比較します。

評価結果は観察だけで終わらせず、GA（遺伝的アルゴリズム）の評価値として利用し、障害物の配置位置を探索します。**モデルを動かす → 条件を変える → 数値で比較する → 結果を配置探索へつなげる**ところまでを、一つの検証環境として扱うことを重視しています。

## Motivation

創発現象やマルチエージェントシステムへの関心から、個々のエージェントに単純な移動ルールを与えたとき、相互作用や空間構造によって集団全体の流れがどのように変化するかを、自分で条件を変えながら確かめられる環境を作りたいと考えました。

単に人が動く様子を可視化するだけではなく、**移動モデルや環境条件を切り替え、同じ基準で評価し、その結果を次の配置探索へ利用できること**を目標としています。

そのため、経路選択・衝突回避・空間条件を独立した要素として扱い、それぞれを変更したときの集団挙動を比較できる構成にしています。

## Architecture

| レイヤー               | 技術                        | 主な役割                                                                                       |
| :--------------------- | :-------------------------- | :--------------------------------------------------------------------------------------------- |
| **Simulation Engine**  | Go                          | 約20Hzの状態更新、経路探索、局所回避、空間条件の管理、描画なし評価シミュレーション、GA配置探索 |
| **Visualization / UI** | JavaScript, p5.js, Chart.js | エージェント描画、壁・スタート/ゴール編集、パラメータ操作、評価・比較結果の可視化              |
| **Communication**      | WebSocket, HTTP API         | リアルタイム状態配信と編集操作、単発の評価・4通り比較・配置探索・最良配置の適用                |

シミュレーション・経路探索・評価・配置探索はGo側で実行し、ブラウザ側は状態の可視化と操作に集中する構成です。

リアルタイムのエージェント状態やマップ編集には **WebSocket**、評価・アルゴリズム比較・GA実行などの単発処理には **HTTP API** を使用します。

マップはJSON形式の設定から読み込みます。開発環境はVS Code Dev Containersで再現可能な構成としています。

## Technical Challenges & Solutions

### 1. 「経路を選ぶ処理」と「人を避ける処理」の分離

人流の挙動を比較するためには、「目的地までの道筋をどう決めるか」と「周囲の人との衝突をどう避けるか」を一体化せず、独立した条件として扱える必要があると考えました。

- **Pluggable Navigation / Avoidance**  
  目的地までの道筋を決める大域経路探索には **A\* / Flow Field**、周囲との衝突を避ける局所回避には **Force-based separation / Social Force Model** を用意し、それぞれ独立に切り替えられる構成としています。
- **2 × 2 Algorithm Comparison**  
  2種の大域経路探索 × 2種の局所回避の4通りを、同じマップ・エージェント数・パラメータ・乱数条件・評価時間で実行し、条件差を比較できるようにします。
- **Path Recalculation**  
  壁の追加・削除・移動時には通行可能領域を更新し、A\*の経路を無効化、Flow Fieldを再構築することで、変更後の空間へ追従させます。

### 2. リアルタイム観察と繰り返し評価の分離

ブラウザ上で人の動きを観察する処理と、多数の条件を繰り返し評価する処理では、必要な処理が異なります。

- **Go + WebSocket**  
  Go側で約50 ms間隔（20 Hz）でシミュレーションを更新し、計算済みのエージェント状態をWebSocketでブラウザへ配信します。
- **Evaluation without Rendering**  
  条件を評価するときは、ライブ表示と同じ移動ロジックを再利用しながら、WebSocket配信や画面描画を行わず、固定時間だけシミュレーションを進めます。
- **HTTP API**  
  現在配置の評価、4通りのアルゴリズム比較、GAによる配置探索などの単発処理はHTTP APIとして分離します。

これにより、観察用と評価用で移動ロジックを二重実装せず、同じモデルをリアルタイム表示と繰り返し実験の両方に利用できる構成としています。

### 3. 比較可能な評価指標と再現性

シミュレーションを比較や配置探索に利用するには、候補ごとの結果を同じ基準で評価し、条件を再現できる必要があります。

#### 評価指標

| 指標                                   | 内容                                                                 | 評価したいこと                       |
| :------------------------------------- | :------------------------------------------------------------------- | :----------------------------------- |
| **平均到達時間** (`avg_goal_time_sec`) | ゴール到達までの時間。評価時間内に未到達の場合は評価時間上限を用いる | より短時間で目的地へ到達できるか     |
| **最大混雑度** (`max_density`)         | 評価中に1つのグリッドセルで観測された最大エージェント数              | 一部の場所に人が集中しすぎていないか |
| **到達率** (`goal_reach_rate`)         | 評価開始時のエージェントのうちゴールへ到達した割合                   | 行き詰まりや未到達が発生していないか |

最大混雑度は実世界の「人 / ㎡」を推定するものではなく、条件間を比較するための簡易指標として扱います。

また、未到達のエージェントを平均到達時間から除外すると、到達率が低い配置ほど平均時間が短く見える可能性があります。そのため、未到達者には評価時間上限を到達時間として与え、全エージェントを平均へ含めます。

#### 乱数条件の分離

比較の再現性を確認できるよう、乱数を以下の2系統に分けます。

- `simulation_seed`: エージェントの初期条件など、評価シミュレーション側の乱数
- `optimizer_seed`: GAの初期個体・選択・交叉・突然変異に用いる乱数

同じ入力条件と2つのseedを指定した場合に、同じ評価・探索結果を再現できる構成としています。

### 4. シミュレーション結果を使った障害物配置探索

人流シミュレーションの評価結果を、GAの候補配置を評価するために利用します。

配置探索では、各障害物の形状そのものを変更するのではなく、**形状を保ったまま配置位置を探索**します。GAでは、平均到達時間だけでなく、混雑や未到達も考慮して候補を評価します。

#### Fitness

```text
平均到達時間
+ 混雑ペナルティ
+ 未到達ペナルティ
```

各障害物の移動範囲には制限を設け、障害物同士の重複、スタート/ゴールとの重複、スタートからゴールへの経路を完全に遮断する配置を無効とします。

最適化後は、初期配置と最良候補について3指標を並べて比較し、ユーザーが選択した場合のみ最良配置をライブマップへ適用します。

### 5. 連続した壁を1つの配置単位として扱う

ブラウザで複数セルにまたがる壁を描いたとき、それぞれのセルを独立した最適化対象にすると、配置探索によって1本の壁がばらばらに分解されてしまいます。

- **WallGroup**  
  1回のドラッグで連続配置した壁セル群を1つの論理オブジェクトとして扱います。内部では基準位置 `origin` と、その位置からの相対セル座標 `cells` を保持します。
- **Shape Invariant**  
  手動移動・GAによる配置探索のどちらでも相対座標は変更せず、グループ全体を平行移動します。回転・拡大縮小・分割は行いません。

WallGroupはユーザー向けの主要機能というより、**「ユーザーが描いた障害物の形を保ったまま配置探索する」ための内部設計**として位置づけています。

## Outcome

本プロジェクトでは、

**移動ルールをモデル化する → ブラウザで集団挙動を観察する → 条件を変えて同じ指標で比較する → シミュレーション結果を使って環境配置を探索する**

という一連の検証フローを、一つのシステムとして扱います。

単一のアルゴリズムを実装することではなく、**数理モデルを交換可能な形で実装し、実験条件を揃えて比較し、得られた結果を次の探索処理へ接続するところまでソフトウェアとして構成すること**を、このプロジェクトの中心に置いています。

## Current Status

現在は、4通りの移動モデル比較、3指標による定量評価、障害物配置を対象としたGA探索を中核機能として開発を進めています。

現実の人流データを用いたパラメータ校正や妥当性検証は行っておらず、実世界の人流予測や安全判断を目的としたシステムではありません。障害物についても、実際の建築壁そのものではなく、配置変更可能な仮設パーティション等を簡略化したモデルとして扱っています。
