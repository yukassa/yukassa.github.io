## Overview

全社的な Google カレンダー導入に伴い、既存の（レガシーな）社内カレンダーツールとの並行稼働期間が発生しました。本プロジェクトでは、Google カレンダー上で作成された予定をリアルタイムかつ正確に旧システムへ同期する連携システムを開発しました。

## Technical Details & Achievements

### 1. 順序保証と並列化の両立

同期処理において最も重要なのは「更新順序の整合性」です。
**AWS SQS (FIFO) のメッセージグループ機能**を活用し、以下のようなイベント駆動アーキテクチャを設計しました。

- **ユーザー単位:** メッセージグループ ID で紐付け、**直列処理**することで更新順序を厳密に保証。
- **システム全体:** 異なるユーザーの処理は**並列化（Lambda の同時実行）**し、全体のスループットを最大化。

### 2. 流量制御（スロットリング）の実装

連携先の旧システムは負荷に弱く、大量の更新リクエストが集中するとダウンするリスクがありました。
SQS と Lambda の同時実行数制御を組み合わせることで、旧システムのキャパシティを超えないようにリクエスト流量を制御する**スロットリング機構**を実装し、安定稼働を実現しました。

### 3. 運用コストの最小化

- **Serverless:** Lambda や DynamoDB を採用し、インフラ管理コストを削減。
- **IaC / CI/CD:** Terraform によるインフラコード化と GitHub Actions によるデプロイ自動化を行い、少人数での運用基盤を構築しました。
